## 二、主要代码实现与说明

### 1. 后端接口手动测试

为保证系统核心功能的正确性和稳定性，我采用了手动测试的方式对后端主要接口进行了验证。主要流程如下：

- 使用Postman接口测试工具，逐一对用户注册、登录、课程管理、签到任务、文件上传等接口进行请求，检查接口返回的数据格式、状态码和提示信息是否符合预期。
- 针对异常输入（如缺少参数、错误的token、无权限操作等）进行测试，确保系统能够正确返回错误提示，防止异常数据入库。
- 对于文件上传、图片访问等功能，手动上传不同格式和大小的图片，验证系统的文件类型校验、大小限制和存储路径是否生效。
- 在前后端联调过程中，配合前端同学进行接口对接，及时修正参数命名、数据格式等不一致的问题。

通过上述手动测试，发现并修复了部分接口在边界条件下的bug，如参数校验不严、错误提示不明确等问题，提升了系统的健壮性和用户体验。

### 2. 前端打包与部署

前端项目采用Vue框架开发，使用`npm run build`命令进行生产环境打包。打包后生成的静态文件通过Nginx部署到服务器，配置了反向代理以实现前后端分离架构下的接口转发。Nginx配置示例如下：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        root /var/www/facecheckin/dist;
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://localhost:5001/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location /uploads/ {
        alias /var/www/facecheckin/uploads/;
    }
}
```

该配置实现了前端静态资源的高效访问和后端API的安全转发，保证了系统在生产环境下的稳定运行。

### 3. 系统功能完善与优化

- **异常处理与错误提示**：对后端所有接口增加了统一的异常捕获和错误日志记录，确保系统在出现异常时能够及时反馈并便于后期排查。例如，在Flask应用中通过全局异常处理器捕获未处理的异常，并返回标准化的错误响应。

- **用户体验优化**：根据用户反馈，优化了前端部分页面的交互逻辑和样式细节，如表单校验提示、按钮禁用状态、加载动画等，提升了系统的易用性和美观度。

- **安全性提升**：加强了接口的权限校验和数据校验，防止未授权访问和非法数据提交。对文件上传接口增加了文件类型和大小的双重校验，防止恶意文件上传。

- **数据库迁移与数据初始化**：使用Flask-Migrate工具完成了数据库结构的自动迁移，并编写了数据初始化脚本，确保系统上线后能够正常使用。

## 三、遇到的问题与解决方案

- **接口兼容性问题**：在前后端联调过程中，发现部分接口的参数格式与前端不一致，导致数据无法正常提交。通过与前端同学沟通，统一了接口参数命名和数据格式，并在后端增加了参数校验和详细错误提示，提升了接口的兼容性和健壮性。

- **生产环境部署难点**：在服务器部署过程中，遇到Nginx反向代理配置不当导致接口无法访问的问题。通过查阅官方文档和社区经验，调整了Nginx的location配置，成功实现了前后端的分离部署和接口转发。

- **数据一致性与安全性**：在多用户并发操作下，部分接口存在数据竞争和一致性问题。通过增加数据库事务和锁机制，确保了数据操作的原子性和一致性。
