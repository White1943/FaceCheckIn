```python
class Course(db.Model):

```     
### 2. 课程模型说明

Course模型是系统中课程信息的核心数据结构，采用SQLAlchemy ORM框架实现。该模型包含课程的基本信息字段，如课程ID(course_id)作为主键、课程名称(course_name)、教师ID(teacher_id)作为外键关联用户表、学期信息(semester)、课程描述(description)、上课时间(start_time)和下课时间(end_time)、上课地点(location)以及创建时间(created_at)。模型通过relationship建立了与用户模型的多对多关系，实现了教师与学生对课程的关联，其中students关系使用secondary参数指定中间关联表，并通过lazy='dynamic'实现延迟加载以提高性能。此外，模型还提供了get_end_time静态方法用于根据标准上课时间自动计算对应的下课时间。
get_end_time具体实现如下：
```python
        def get_end_time(start_time_str):
            """根据上课时间获取下课时间"""
            time_mapping = {
                '08:15': '09:45',
                '10:05': '11:35',
                '13:00': '14:30',
                '15:00': '16:30',
                '18:00': '19:30',
                '20:00': '21:30'
            }
            return time_mapping.get(start_time_str)
```
该函数通过时间映射表time_mapping将上课时间与下课时间进行映射，如果上课时间不在映射表中，则返回None，通过这种方式可以确保上课时间与下课时间的一致性，避免出现时间冲突，也可以获得课程的结束时间。

### 5. 学生管理功能实现

#### 查看课程学生列表

```python
@course_bp.route('/teacher/courses/<int:course_id>/students', methods=['GET'])
@jwt_required()
def get_students_for_course(course_id):
    try:
        teacher_id = int(get_jwt_identity())
        course = Course.query.get(course_id)
        if not course:
            return Result.error("课程不存在", code=404)
        if course.teacher_id != teacher_id:
            return Result.error("无权查看此课程的学生", code=403)
        students = course.students.all() 
        student_data = []
        for student in students:
             s_dict = student.to_dict()
             s_dict['userId'] = student.user_id
             student_data.append(s_dict)
        return Result.success(data={'items': student_data, 'total': len(student_data)})
    except Exception as e:
        current_app.logger.error(f"Error fetching students for course {course_id}: {e}")
        traceback.print_exc()
        return Result.error("获取学生列表失败")          
```
验证当前用户是否有权限查看该课程，防止越权访问其他教师的课程数据，其次将学生对象转换为字典格式，并返回数据和总数。
这个查看选课学生的功能核心重点在下方代码，其利用了SQLAlchemy模型中back_populates参数实现了双向关联。在Course模型中，通过定义`students = db.relationship('User', secondary='course_students', back_populates='enrolled_courses', lazy='dynamic')`建立了与User模型的多对多关系，而User模型中相应地有`enrolled_courses = db.relationship('Course', back_populates='students')`。这种双向关联使得我们可以：

1. 通过`course.students`直接获取选修该课程的所有学生对象的查询集
2. 由于设置了`lazy='dynamic'`，`course.students`返回的是一个查询对象而非列表，因此可以调用`.all()`方法获取所有学生
3. 遍历学生列表时，每个student对象都是完整的User实例，可以访问其所有属性和方法
4. 通过`student.to_dict()`将学生对象转换为字典格式，便于JSON序列化返回给前端

这种ORM关系映射大大简化了数据库查询操作，无需手动编写复杂的JOIN语句。
 

#### 移除学生
教师查看选课中的学生，可以进行移除学生的操作，主要代码如下：
```python
@course_bp.route('/teacher/courses/<int:course_id>/students/<int:student_id>', methods=['DELETE'])
@jwt_required()
def remove_student(course_id, student_id):
    try:
        user_id = int(get_jwt_identity())
        course = Course.query.get(course_id)
        student = User.query.get(student_id)
        
        # 校验权限和数据
        if not course or course.teacher_id != user_id:
            return Result.error("无权操作此课程", code=403)
        if not student:
            return Result.error("学生不存在", code=404)
        if student not in course.students:
            return Result.error("学生未选修此课程", code=400)
```
同样需要验证当前用户是否有权限操作此课程，其次验证学生是否存在，最后验证学生是否选修该课程，如果都无误，则进行移除学生的操作。

```python            
        # 移除学生
        course.students.remove(student)
        db.session.commit()
        return Result.success(message="学生已移除")
        
    except Exception as e:
        db.session.rollback()
        current_app.logger.error(f"移除学生失败: {str(e)}")
        return Result.error("移除学生失败")
```
从课程中移除学生，并提交事务，返回成功信息。同样是用到了SQLAlchemy的ORM关系映射，通过`course.students.remove(student)`从课程的学生关系中移除指定学生，并提交事务保存修改。

## 三、总结

本周通过课程管理模块的开发，深入掌握了以下技术点：

1. **RESTful接口设计**：按照资源化的方式设计API端点，合理使用HTTP方法和状态码，使接口更加规范和易用。


2. **数据库事务管理**：使用SQLAlchemy的事务机制，使用db.session.rollback() 回滚事务，保证数据操作的原子性，在异常情况下能够正确回滚。

3. **关联关系操作**：通过ORM的关系属性，方便地处理课程与学生之间的多对多关系，实现学生管理的各项功能。本周深入使用了SQLAlchemy的关系映射功能，通过定义模型间的关联关系，实现了课程与学生之间的多对多管理。在实践中发现ORM关系属性的优势显著：它不仅简化了复杂的SQL查询，还提供了直观的对象操作方式；通过延迟加载策略提高了查询效率；使用简洁的语法如remove()和append()方法管理关联数据，无需手动操作中间表；双向关系映射使得可以从任一方便捷地访问关联数据；同时级联操作确保了关联数据的一致性。这些特性大大提高了代码的可读性和维护性，使复杂的数据关系操作变得简单高效。
