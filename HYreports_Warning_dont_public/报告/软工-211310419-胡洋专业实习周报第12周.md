## 一、课题进展情况

本周的主要任务是"数据库设计与优化"。随着系统功能的不断扩展，数据量逐步增加，数据库的结构设计、查询效率和数据一致性对系统性能和稳定性提出了更高要求。本周我对考勤系统的核心数据表结构进行了梳理和优化，重点关注了表结构规范、索引优化、复杂查询和事务处理等方面，提升了系统的数据管理能力和运行效率。

具体进展如下：

1. **数据表结构梳理与规范化**  
   对现有的用户表、课程表、课程学生关联表、签到任务表、签到记录表等核心表结构进行了梳理，确保字段命名规范、数据类型合理、主外键关系清晰。例如，`course_students`表采用联合主键（`course_id`+`student_id`），保证同一学生不能重复选同一门课程；`attendance_records`表通过唯一索引防止同一学生对同一签到任务重复签到。

2. **索引优化与查询效率提升**  
   针对系统中常用的查询场景（如按用户ID、课程ID、签到任务ID等查询），为相关字段添加了合适的索引。例如，在`attendance_records`表中为`student_id`、`task_id`等字段建立索引，大幅提升了签到记录的查询速度。通过EXPLAIN分析SQL执行计划，发现并优化了部分慢查询。

3. **复杂查询与多表关联优化**  
   在实现如"教师端查看课程下所有学生的签到情况"、"学生端查询自己的历史签到记录"等功能时，涉及多表关联查询。通过合理设计SQL语句和ORM查询，减少了不必要的嵌套和数据冗余。例如，采用SQLAlchemy的`join`和`filter`方法高效获取所需数据，并通过分页查询减少一次性数据量。

4. **事务处理与数据一致性保障**  
   对涉及多表写操作的接口（如选课、退课、签到、申诉等），均采用数据库事务机制，确保操作的原子性和数据一致性。出现异常时自动回滚，防止数据部分写入导致的不一致问题。

 

## 二、主要实现细节与说明

- **表结构设计举例**  
  以`attendance_records`表为例，采用如下结构：

  ```python
  class AttendanceRecord(db.Model):
      __tablename__ = 'attendance_records'
      id = db.Column(db.Integer, primary_key=True)
      task_id = db.Column(db.Integer, db.ForeignKey('attendance_tasks.task_id'), nullable=False)
      student_id = db.Column(db.Integer, db.ForeignKey('users.user_id'), nullable=False)
      status = db.Column(db.String(20), default='正常')
      sign_time = db.Column(db.DateTime, nullable=False)
      # ... 其他字段 ...
      __table_args__ = (db.UniqueConstraint('task_id', 'student_id', name='uix_task_student'),)
  ```
  这样设计可以防止同一学生对同一签到任务重复签到。

- **索引优化举例**  
  在`course_students`、`attendance_records`等表的外键字段上添加索引：

  ```python
  CREATE INDEX idx_student_id ON attendance_records(student_id);
  CREATE INDEX idx_task_id ON attendance_records(task_id);
  ```

- **复杂查询优化**  
  使用SQLAlchemy的`join`和`filter`实现多表高效查询。例如，查询某课程下所有学生的签到情况：

  ```python
  records = db.session.query(AttendanceRecord, User).join(User, AttendanceRecord.student_id == User.user_id).filter(
      AttendanceRecord.task_id == task_id
  ).all()
  ```
