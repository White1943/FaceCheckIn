## 一、课题进展情况

本周的主要任务是“用户登录安全优化与公钥加密机制实现”。随着系统用户量的增加和安全需求的提升，保障用户登录过程中的数据安全成为重点。本周围绕登录密码的加密传输、后端解密、密钥管理等方面进行了优化和实践，显著提升了系统的安全性。

具体进展如下：

1. **前后端非对称加密登录流程设计**  
   - 为防止用户密码在网络传输过程中被窃取，采用了RSA非对称加密方案。前端在登录时通过接口获取后端生成的公钥，使用公钥对用户输入的密码进行加密，后端收到加密数据后用私钥解密，整个过程保证了密码在传输过程中的安全性。
   - 在`app/auth/views.py`中实现了`/public-key`接口，前端可通过该接口获取公钥字符串，保证每次登录都能动态获取最新的加密公钥。

2. **后端公钥私钥生成与管理**  
   - 后端在服务启动时自动生成一对RSA密钥对，公钥用于前端加密，私钥仅保存在后端用于解密，保证密钥安全。
   - 公钥通过PEM格式转换为字符串，去除头尾标识后返回给前端，便于前端加密库直接使用。

   关键代码片段如下（`app/auth/views.py`）：
   ```python
   private_key = rsa.generate_private_key(
       public_exponent=65537,
       key_size=2048,
       backend=default_backend()
   )
   public_key = private_key.public_key()

   @auth_bp.route('/public-key', methods=['GET'])
   def get_public_key():
       pem = public_key.public_bytes(
           encoding=serialization.Encoding.PEM,
           format=serialization.PublicFormat.SubjectPublicKeyInfo
       )
       pem_str = pem.decode('utf-8')
       key_str = pem_str.replace('-----BEGIN PUBLIC KEY-----\n', '').replace('\n-----END PUBLIC KEY-----\n', '')
       return Result.success(data={'publicKey': key_str})
   ```

3. **后端登录解密与校验流程**  
   - 登录接口接收到前端加密后的密码后，先用私钥进行解密，再进行用户身份校验。
   - 解密失败或数据异常时，返回明确的错误提示，防止异常数据影响系统安全。

4. **安全性与用户体验提升**  
   - 前端无需明文传输密码，极大提升了登录过程的安全性。
   - 后端对解密、用户校验、异常处理等流程进行了细致优化，保证了系统的健壮性和安全性。
   - 登录失败时返回统一的错误码和提示信息，便于前端处理和用户理解。

## 二、主要实现细节与说明

- **密钥生成与管理**  
  后端采用`cryptography`库动态生成RSA密钥对，公钥通过接口暴露给前端，私钥仅在后端内存中使用，保证密钥安全。

- **前端加密与后端解密流程**  
  前端通过`/public-key`接口获取公钥，使用加密库（如JSEncrypt）对密码加密后提交，后端用私钥解密后再进行数据库校验。

- **异常处理与安全提示**  
  对于解密失败、参数缺失、用户不存在等异常情况，后端均返回统一格式的错误响应，防止信息泄露。

- **接口返回结构统一**  
  所有接口均通过`Result.success()`和`Result.error()`返回，保证了前后端交互的一致性和可维护性。
